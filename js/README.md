# Support Gate — веб-клиент

UMD-бандл с окном обращения в поддержку: справочник категорий, вложения и
отправка через Support Gateway. Категории, лимиты и язык приходят с сервера
(`GET /v1/form`), поэтому менять их можно без релиза игры.

## Подключение

Бандл отдаёт сам сервис: `https://support.flushee.work/sdk/v1/support_gate.js`
Копировать его в репо игры не нужно.

```html
<script src="https://support.flushee.work/sdk/v1/support_gate.js"></script>
<script>
  SupportGate.init({
    endpoint: 'https://support.flushee.work',
    token: sessionToken,        // строка или функция, возвращающая свежий токен
  });

  document.getElementById('help').addEventListener('click', function () {
    SupportGate.open();
  });
</script>
```

### Оформление

Попап и встроенная форма используют тёмную тему игрового портала XOffers:
розовый акцент, скруглённые поля и SVG-иконки. Тема не зависит от настроек ОС.
Шрифты Barlow и Sora используются, если они загружены страницей; иначе —
системный шрифт. SDK сам не подключает внешние шрифты. Их можно переопределить
через CSS-переменные `--sg-font-body` и `--sg-font-heading` на контейнере.

Для `mount` задайте высоту переданного контейнера, если форма должна помещаться
в ограниченный фрейм: тело прокручивается, кнопка отправки остаётся внизу.
Колонки учитывают ширину самого контейнера, даже на широкой странице.

### Короткая форма для платёжки

Передайте известные поля через `preset` и включите `compact`. Почта
предзаполняется из токена и остаётся редактируемой. Игроку остаются адрес для
ответа, описание, вложения и поля, которые ещё нужно заполнить. Пример для обращения о неполученной покупке:

```js
SupportGate.mount(document.getElementById('support'), {
  targetId: 'booty_heroes',
  compact: true,
  preset: {
    category: 'payment',
    subcategory: 'missing_purchase',
    subject: 'Покупка не пришла',
    extra: { transaction_id: 'order_12345' },
  },
});
```

Те же параметры доступны у `open`. ID категорий, подкатегорий и значения
select-полей должны существовать в справочнике шлюза. `extra` применяется
только к указанной категории; без `compact` поля просто предзаполняются.
Неизвестные или некорректные значения не скрываются. Серверная ошибка поля
раскрывает его для исправления. Тема и платёжные данные видны кратко над
описанием; почта и незаполненные обязательные поля остаются обычными контролами.
Скрытые значения отправляются и проверяются сервером.

### Токен сессии

`token` — JWT HS256, который выпускает **бэкенд игры** своим секретом (срок
жизни 15 минут). Секрет игры и учётки Jira в клиент не попадают никогда. Если
токен живёт меньше сессии окна, передавайте функцию:

```js
SupportGate.init({
  endpoint: 'https://support.flushee.work',
  token: hint => myGame.freshSupportToken(hint),
});
```

Истёкшую сессию (`401`) клиент обновляет сам и повторяет запрос с тем же
`Idempotency-Key`: функция вызывается ещё раз с `{reason: 'expired'}` — пора
сбросить кэш; если она вернёт тот же токен или токен задан строкой, сессия
продлевается через `POST /v1/session/refresh` (до 3 часов от выпуска). Ошибку
«сессия истекла» игрок видит, только когда не помогло и это; страница `/form`
в этом случае просит открыть её из игры заново.

`myGame.freshSupportToken` — функция игры: кэширует токен текущего окна и
сбрасывает кэш при `hint?.reason === 'expired'`. Без `targetId` игра сама
создаёт новый `jti` на каждое открытие, сохраняет его при обновлении токена
и вызывает `init` для новой сессии. В режиме с `targetId` это делает SDK
(см. раздел про портал ниже).

В токене: `iss` — идентификатор игры, `sub` — игрок (пустой для анонима), `ctx` —
контекст (`locale`, `platform`, `game_version`, …). Если в `ctx` есть
`email`, поле почты предзаполнено и доступно для правки. При отправке SDK
всегда передаёт адрес из формы: `email` обязателен, подстановки из токена нет. Пароли,
токены и данные карт в `ctx` не принимаются. `tags` (список) становятся метками
тикета в Jira — сегмент, плательщик, канал: это знает бэкенд игры, а не форма.
Игроку метки не видны.

## Страница `/form`

Для клиентов без веб-движка (Unity, десктоп) шлюз отдаёт готовую страницу
`https://support.flushee.work/form#token=<jwt>` с этой же формой во весь экран
(`SupportGate.hosted(host)`): токен берётся из фрагмента адреса — он не уходит
на сервер — и сразу стирается из адресной строки. Без токена страница объясняет,
что её открывают из игры.

## API

| Метод | Что делает |
| --- | --- |
| `SupportGate.init(options)` | создаёт клиента; повторный вызов заменяет настройки |
| `SupportGate.open(options?)` | открывает модальное окно с формой |
| `SupportGate.close()` | закрывает окно |
| `SupportGate.mount(host, options?)` | встраивает форму в свой контейнер |
| `SupportGate.getInstance()` | клиент для своей вёрстки |

`options`: `onResult(result)` — итог окна, `onClose()` — при закрытии окна,
`onSubmitted(ticket)` — после успешной отправки (то же, что `sent`).

`result.status`:

| | Когда | Поля |
| --- | --- | --- |
| `sent` | обращение принято, один раз | `ticketId` (`tkt_…`), `issueKey` (`SUP-…` или `null`, пока воркер не доставил), `ticket` |
| `error` | каждая неудачная попытка — игрок может повторить | `stage` (`load` — форма не загрузилась, `submit` — не ушло), `message`, `kind`, `httpStatus`, `code` |
| `closed` | окно закрыли, ничего не отправив | — |

Текст `message` не переведён и для показа не предназначен — это для лога игры.

### Своя вёрстка

Если форма игры своя, нужен только клиент — DOM он не трогает:

```js
const client = SupportGate.init({endpoint, token});

const config = await client.form();              // категории, лимиты, prefill
const attachment = await client.upload(file);    // файл уходит прямо в хранилище
const ticket = await client.submit({
  category: 'payment',
  subcategory: 'refund',
  subject: 'Не пришла покупка',
  description: '…',
  email: 'player@example.com',
  extra: {payment_method: 'apple'},
  attachment_ids: [attachment.attachment_id],
});
```

`submit` вторым аргументом принимает ключ идемпотентности: повтор после сетевой
ошибки с тем же ключом вернёт то же обращение, а не создаст второе. Без
аргумента ключ генерируется на каждый вызов.

Ошибки транспорта и проверок SDK — `SupportGateError`: `kind` (`invalid_request` / `network` /
`http` / `parse`), `status`, `code`, `fields` (ошибки по полям формы) и
`transient` — признак того, что повтор имеет смысл.
Исключение провайдера токена передаётся как есть и может быть обычным `Error`;
в `onResult` для него `kind` и `code` равны `null`, а `httpStatus` — `0`.

## Портал: фиксированный адресат или выбор игры

Используется тот же SDK. Бэкенд портала хранит привязки аккаунтов и выпускает
JWT своим секретом; браузер передаёт выбранный ресурс, а игровой user ID
бэкенд определяет самостоятельно. В админке шлюза ресурс должен иметь тип
`portal` и разрешённый список целевых игр.

```js
SupportGate.init({
  endpoint: 'https://support.flushee.work',
  token: async ({targetId, jti, reason}) => {
    const response = await fetch('/api/support/token', {
      method: 'POST',
      headers: {'Content-Type': 'application/json'},
      body: JSON.stringify({targetId, jti, reason}),
    });
    if (!response.ok) throw new Error('Cannot obtain support token');
    return (await response.json()).token;
  },
});

// Ссылка на странице игры: адресат фиксирован, переключателя нет.
SupportGate.open({targetId: 'booty_heroes', onResult: result => console.log(result)});

// Общая кнопка поддержки: список предоставляет портал по привязкам аккаунтов.
SupportGate.open({
  targetId: 'portal',
  targets: [{id: 'portal', label: 'Портал'}, {id: 'booty_heroes', label: 'Booty Heroes'}],
});
```

`/api/support/token` в примере — ручка **бэкенда портала**, не шлюза.
Она определяет пользователя по сессии портала, проверяет доступность игры
и его серверную привязку, затем подписывает JWT с игровым ID в `sub`.
Для самого портала `sub` содержит ID пользователя портала. Контракт токена
и проверки — в [инструкции интеграции](../docs/integration.md#подключение-портала).
Те же `targetId`/`targets` доступны у `mount`. Список включает переключатель;
без `targetId` форма ждёт выбора до запроса токена. Для переключения нужен
провайдер-функция, список должен быть непустым и иметь уникальные ID.

SDK создаёт `jti` при открытии формы и каждой смене адресата; провайдер должен
сохранять его в JWT и кэшировать токен по паре `targetId`/`jti` в пределах
авторизованного аккаунта. Кэш в примере не показан. На `expired`
получает те же поля вместе с `reason`. Конфигурация `/v1/form` проверяется на
соответствие выбранному адресату. Если используете только клиент, доступен
`SupportGate.getInstance().forTarget(targetId)`.

При переключении сохраняются тема, текст, совместимые поля и локальные файлы;
вложения загружаются заново для новой сессии. Адрес для ответа из черновика
сохраняется и остаётся редактируемым. Ошибка загрузки файла оставляет его в форме с кнопкой повтора;
отправка ждёт успешной загрузки или явного удаления файла.
Ошибка загрузки формы не теряет черновик, поздний ответ прежней
игры не меняет текущую форму. После начала отправки переключение блокируется:
при сетевой/5xx/parse-ошибке повтор использует прежние адресат, тело и ключ.
После явного HTTP 4xx можно исправить форму или сменить адресата.

В результатах портальной формы дополнительно есть `targetId`. Старые игровые
вызовы и форма без новых параметров сохраняют прежнее поведение. При удалении
встроенной формы вызовите `form.destroy()` для отмены запросов и очистки ресурсов.
Общий запрос справочника может завершиться после удаления формы; его поздний
ответ не отображается в удалённой форме и доступен другим экземплярам клиента.

## Разработка

```sh
npm install
npm run typecheck
npm test          # собирает dev-бандл и гоняет тесты по нему (jsdom)
npm run build     # прод-сборка в dist/support_gate.js
```

`demo/index.html` открывает окно против локального сервиса и умеет сам получить
токен через `POST /v1/dev/token` (ручка живёт только при `SG_ENV=local`).

Сборка — Vite в библиотечном режиме (`vite.config.mts`), как и в `admin-ui`:
один UMD-файл с глобальным `SupportGate`, без внешних зависимостей. В прод-сборке
`__SG_DEBUG__` становится литералом `false`, и отладочный лог из бандла вырезается.
